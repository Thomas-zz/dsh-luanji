# 乱记：本地优先 + 自托管 API 同步

2026-11-09，最终开发交接方案。本方案取代此前 Git 首期方案及 output 中的讨论稿。尚未实施、部署。

首要目标：让项目所有者自己在电脑和手机上舒服、可靠地使用乱记；独立开源分享是第二目标。不以未知的用户规模增加首期复杂度。本文件是后续开发的统一依据。

## 1. 本期交付与边界

现在实现服务器 API 同步，默认关闭。插件安装后纯本地可用，无账号、无数据库安装、无云端依赖。需要同步的用户自行部署配套服务，或连接实现兼容协议的服务。

交付：DSH 插件设置页及同步引擎、可独立部署的配套服务 luanji-sync-server（首期放本仓库 server/）、最小手机网页、Docker Compose 部署模板、协议说明、部署 Prompt。部署 Skill 可随后将同一流程包装，不成为同步前置条件。

暂不做：Git/WebDAV/S3 等多适配器、公共云托管、多租户注册收费、通用数据平台、工作台接入、实时协同、端到端加密、手机原生 App。当前信任用户自有服务器，内容在服务端可读，必须如实告知。

## 2. 最小架构

DSH 插件读写本地 notes.json → 可选同步引擎 → HTTPS API → 个人同步服务（SQLite + 附件目录）。手机通过服务随附网页访问同一 API。

本地先保留已有 JSON store，不把文件拆分或迁移 SQLite 当成同步前提。保存本地数据和待同步状态必须在同一次原子文件替换中完成；不能另写队列造成崩溃丢操作。附件先保留兼容读取旧 base64 的能力，云端使用独立二进制附件，JSON 导出仍完整包含附件。

后端一个实例服务一个个人数据空间：Node.js/TypeScript + SQLite，数据库随服务打包，无需用户另外安装数据库。一个容器提供 API 和手机网页，一个持久化数据目录，复用反向代理做 HTTPS。只有服务器部署者需要操作 Docker；插件普通使用者不用。

服务独立于 Block6，不复用其管理员会话、数据库表或业务代码。共享现有机器和 Nginx 即可。以后各插件独立开源，业务服务按实际需要开发，不提前拆微服务或统一后端。

测试连接为只读：检查认证、协议版本、稳定服务/数据空间 ID，并获取记录数量；不上传记录。状态区分地址不可达、证书问题、认证失败、协议不兼容。强制远程 HTTPS，仅本机开发允许 HTTP；请求不跟随跨源重定向，认证不放 URL。

测试成功后显示“本机 N 条、云端 M 条”，首次默认合并两边内容；说明正文、引用来源、图片会同步，草稿/本机配置不参与。首期采用全库同步，不做逐条记录权限或选择性同步；启用前明确告知带引用内容也会上云。

按钮：[启用同步并合并]。同 ID 同内容去重；同 ID 内容不同且没有共同版本时保留两份，不按时间覆盖，不提供首版覆盖全库选项。首次合并前生成本地完整快照。

开启后：

```text
云端同步                                      [开启]
服务：notes.example.com
状态：已同步 / 正在同步 / 等待网络 / 需要处理冲突
最近成功：今天 14:32       待同步：2 条

[立即同步] [查看详情] [修改连接]
```

关闭同步立即停止新网络操作并尝试取消在途请求；已经被服务器接收的操作可能已提交，不能承诺撤回，下次通过 opId 对账；不删除本地或云端数据。详情页展示错误、待同步数、冲突和重试，不展示密钥/正文日志。修改服务或数据空间视为新连接，重新预览合并，不沿用旧游标；未同步内容保留。撤销设备密钥与删除云端数据分开，首期不提供一键清空云端。

## 4. 同步规则

- 本地保存立即成功，联网失败不影响继续编辑。启动、保存后短暂防抖、恢复连接以及手动按钮触发同步；运行期间低频拉取，失败指数退避。单设备单同步循环，不使用 WebSocket。
- 每条记录有稳定 id；完整同步正文、不可变引用及来源、附件引用。不得延续旧实现“带引用整条跳过”的行为。
- 每个操作含 opId、记录 id、baseRev、操作内容。服务端通过 baseRev 比较后提交新 rev；opId 幂等检查与数据变更在同一数据库事务中完成。同 opId 不同内容拒绝。
- 客户端上传使用冻结的操作快照。请求期间发生的新编辑不能被旧响应清除；收到旧确认只确认对应操作，新编辑重新以新基础版本入队。
- 通过服务端单调递增 seq 和持久化变更日志拉取，分页有固定上界；落盘后才能推进本地游标。未上传的本地修改不允许被拉取静默覆盖。
- 删除保留 tombstone；第一版不自动清理变更日志、幂等记录和墓碑。先以个人规模运行，未来再实现过期设备重新全量同步策略。
- 冲突使用 baseRev 识别，不靠设备时间排序。第一版保留本地和远端两个版本，在冲突面板提供保留本地/远端/两份；删除对编辑也需处理。未解决时暂停该条，其余记录继续同步。
- 附件使用内容哈希校验、独立上传和下载。附件成功后再提交引用；下载不完整显示缺失/重试，不把空附件集合写回。限制单文件、请求大小和总容量；错误必须可见。
- 草稿和设备设置本期不跨设备同步。客户端说明“本机已保存”和“已同步”的区别。
- 原有旧云端导入导出停用自动触发；新旧协议不能同时写同一库。已有配置引导迁移，不能把新协议请求直接发给旧接口。

## 5. 版本化 API 草案

| 接口 | 职责 |
| --- | --- |
| GET /api/sync/v1/info | 认证后返回协议版本、稳定 spaceId、数量与限制 |
| GET /api/sync/v1/changes?cursor=... | 返回有界分页变更、下一游标及分页上界 |
| POST /api/sync/v1/ops | 提交有 baseRev、opId 的创建/更新/删除操作，逐项确认或冲突 |
| PUT /api/sync/v1/blobs/:hash | 上传附件，校验内容哈希，幂等 |
| GET /api/sync/v1/blobs/:hash | 鉴权下载附件 |

在实现前确定请求/响应样例、错误码、限制、全量初始化和分页语义，提交协议文档及契约测试。客户端不绑定 SQLite，只绑定协议。手机编辑也走相同的版本和幂等规则，不能绕过冲突控制。

## 6. 手机首期

配套服务附带响应式网页：登录、查看、搜索、创建、编辑、图片、删除恢复。手机联网访问自己的 HTTPS 地址即可；本期手机为在线入口，不承诺离线编辑、后台同步或 PWA。

手机号/邮箱注册、找回密码、公共用户系统不做。部署时由管理命令创建手机登录口令（哈希存储）与独立设备 Token；手机使用 Secure、HttpOnly、SameSite 会话，并校验来源/CSRF、限制登录尝试。桌面 Token 不存浏览器 localStorage。后续手机离线体验另行迭代，不能把网页缓存当可靠副本。

## 7. 部署与密钥

提供版本固定的 Docker 镜像/构建文件和 compose.yaml，挂载数据目录。首期以命令生成/撤销独立设备 Token，不建设复杂账号后台；Token 仅创建时显示，服务端存哈希。插件只在 Host 侧使用 Token，优先系统安全存储，不具备时用权限 0600 的私有配置文件，不回传页面、不写日志、不包含在导出包中。

不要求为开启同步先实现二维码。后续可用短期、一次性配对码减少复制密钥；不把长期密钥放 URL 或普通二维码链接。

HTTPS 与鉴权必需；API 端口仅回环/内部容器网络可访问，反向代理对外。上传文件不作为任意 HTML 静态站点执行；内容类型、路径、大小校验。同步服务凭据与备份删除权限分离。

每日生成 SQLite 一致性快照，不能直接复制正在写入的数据库文件；备份数据库和附件，并加密复制到独立位置。明确同步不是备份，先验证恢复一次再依赖它。公开仓库不包含服务器地址、个人笔记、密钥或生产配置。

用户现有服务器 2026-11-09 只读检查为 2 核、约 4GB 内存、根盘剩余约 42GB，已有 Nginx、PostgreSQL、Docker。可复用，无需购机；新服务独立目录/进程/凭据。部署前重新检查资源和反向代理，不能覆盖现有站点配置或清理旧表。本方案未执行生产变更。

## 8. AI 辅助部署的定位

真实同步由确定性的插件/服务代码执行，不由 AI 定时复制记录。AI 只负责安装、检查、升级和排障。没有 AI 的用户可以照 README 部署；有 AI 的用户复制 Prompt；使用特定 agent 的用户可安装包装同一流程的 Skill。

首期发布部署 Prompt，不为包装 Skill 延迟同步交付。AI 不接触用户正文、不在对话打印密钥，交付可直接填写的地址和在服务器私密文件中领取 Token 的方式。自己已有数据库但无同步 API 的用户，优先部署配套服务，不让 AI 随意生成另一套协议。

### 可交给部署 agent 的 Prompt 模板

请根据我指定的 luanji-sync-server 仓库和固定版本部署个人乱记同步服务。先读取该版本 README、compose 和协议文档，再只读检查服务器 OS、Docker、磁盘、端口、域名和现有反向代理。使用独立目录、持久化数据卷和独立凭据，保持现有应用运行。配置有效 HTTPS、接口鉴权、请求限制，生成独立设备 Token 和手机登录凭据，不在聊天或日志打印秘密。生成一致性备份及恢复说明。用临时测试记录验证连接、上传、拉取、重复请求和鉴权失败；不读取或上传真实笔记。交付服务地址、密钥私密领取方法、手机地址、备份位置、版本、检查结果与回滚方法。涉及尚未授权的生产变更时先展示具体改动并取得授权；缺域名或证书信息时报告缺项，不擅自关闭 TLS 验证。

发布时用真实仓库与版本替换占位说明；不虚构可运行的镜像地址或安装命令。

## 9. 开发顺序与验收

1. 协议 + 最小服务：SQLite、认证、变更日志、幂等/冲突、附件、compose；使用临时目录完成契约测试。
2. DSH 接入：保留 store 和 UI，在同一次本地写入中记录同步状态，实现同步循环和设置表单。旧数据先备份，升级可回退，不读写测试环境外的真实笔记。
3. 手机网页：同一 API 跑通电脑到手机及手机到电脑；不另写一套绕过版本检查的 CRUD。
4. 文档和部署 Prompt：空机器部署验证、备份恢复验证，随后在用户服务器准备独立部署。生产发布授权按当前会话范围处理，不把方案请求当发布授权。

验收必须包含：未开启不联网；测试连接不上传；关闭不删除；断网保存/恢复同步；两个客户端修改冲突不丢；请求成功响应丢失重试不重复；请求期间再次编辑不丢；删除不会被旧设备复活；引用完整；附件失败重试；首次双边数据合并；改服务不复用游标；错误凭据拒绝；本地损坏不清空；备份可恢复。

交付代码、协议、设置界面、迁移说明、部署模板/Prompt、验证报告。报告区分本地完成、服务器部署和多端实测，不把 README 或构建通过写成上线成功。

## 11. 数据模型和状态约定

### 云端业务对象

```json
{
  "id": "uuid",
  "text": "我的想法",
  "source": "selection",
  "created_at": 1790000000000,
  "updated_at": 1790000000000,
  "quote": {
    "id": "quote-uuid",
    "text": "被引用的原文",
    "origin": {"role": "assistant", "model": "模型名", "sessionId": "来源会话"},
    "anchor": {"start": 0, "end": 7, "exact": "被引用的原文"}
  },
  "attachments": [
    {"id": "image-uuid", "hash": "sha256-hex", "mime": "image/png", "size": 12345, "name": "图片.png"}
  ],
  "deleted_at": null
}
```

示例省略部分来源字段，实际须保留现有 origin、anchor 全部字段，不能因例子简写丢数据。quote 可为空；云端以完整记录为写入单元，本地仍可使用 records/quotes 分离结构并进行映射。服务器 rev、seq 与上述业务时间分开，更新时间不参与冲突胜负判断。

服务端最少需要 records、changes、operation_receipts、blobs，以及配置/认证所需存储；无需通用实体关系平台。records 保存当前版本和软删除状态，changes 保存不可变的变更快照，不能仅存指向可变当前行的引用。写 records、changes、操作回执必须同事务。数据库主键和唯一索引落实幂等，不依靠应用内先查再写。

### 本地状态

把新的 sync 元数据放进现有 notes.json 的新格式版本，跟业务更新一起提交。包括绑定数据空间、游标、每条已确认 rev、待提交操作/快照、待解决冲突。密钥不放这里，而在 Host 私密配置中。

同步关闭仍可新增、修改、删除：保留已有绑定的版本及待同步状态，重新开启相同空间后能正确追赶。首次未绑定不需要生成无限操作历史，只标记本地未发布状态。软删除记录在 UI 隐藏，但不能立刻物理移除，否则无法同步删除。

新格式迁移前保留完整 v2 备份；升级失败保持原文件。现有 normalize、导入、导出路径必须显式处理新元数据，避免旧归一化函数丢掉队列。普通可迁移导出包含全部业务数据和附件，但不带设备凭据、游标和在途操作；用于灾难恢复的备份可包含本地同步状态，恢复后仍需校验服务身份。

第一版本地库限定单写入 Host，串行处理本地变更与同步落盘；增加独占锁及异常退出恢复，避免另一个 Host 持有旧内存覆盖内容。

### 空间身份与恢复

服务持久化 spaceId 和 generation，客户端绑定二者。空服务重建、服务器从旧快照恢复后必须更换 generation；客户端发现变化停止增量同步并走重新合并，不能拿旧游标跳过恢复后的数据。管理恢复命令负责这个步骤，写入备份恢复说明。

## 12. API 请求与分页的确定语义

下面是实现基准；开发者可补充字段但不得删除幂等、版本、空间身份约束。请求含 Authorization: Bearer <device-token>；网页使用同源安全会话。认证成功后才返回库的数量和元信息。

`GET /api/sync/v1/info` 返回：

```json
{"protocolVersion":1,"spaceId":"uuid","generation":"uuid","activeCount":128,"limits":{"maxTextChars":20000,"maxAttachments":6,"maxBlobBytes":2097152}}
```

上例限制沿用当前插件大致范围；开发时根据实际图片编码限制统一前后端和 README，不能 UI 写 20MB、协议实际只收 2MB 而无说明。入口图片可先压缩，API 以最终上传字节计限额。默认总容量建议 5GiB，可在服务端配置；达到容量返回明确错误，本地内容保留。

`POST /api/sync/v1/ops` 首期可一次只提交一条，避免批处理复杂度：

```json
{"spaceId":"uuid","generation":"uuid","opId":"uuid","recordId":"uuid","baseRev":0,"kind":"put","record":{"id":"uuid","text":"笔记","quote":null,"attachments":[],"created_at":1790000000000,"updated_at":1790000000000,"source":"ui","deleted_at":null}}
```

baseRev=0 代表创建。已有记录更新必须携带所知 rev，删除使用 kind=delete 和 baseRev。成功返回 opId、recordId、rev、seq；baseRev 不匹配返回 409 和远端当前版本/内容。记录不存在、已删除、附件缺失均返回结构化结果，不当成成功。

opId 回执在同一空间内唯一；重试相同请求返回原结果，同 opId 不同请求体拒绝。网络不确定时始终重试原 opId 和原 payload，不能重新生成操作。冲突解决是新 opId，基于最新远端 rev；再次冲突继续保留双方。

`GET /api/sync/v1/changes?cursor=0&limit=100` 首次在同一一致性读中确定 upperBound，返回 seq 大于 cursor 且不大于 upperBound 的变更、nextCursor、hasMore。后续页携带同一 upperBound；结束后才能开始新的分页轮次。每个条目包含 seq、rev、完整记录或墓碑。首版保留全部日志，因此 cursor=0 可重放整个库；已删除数据也参与初始化，避免旧记录复活。

返回建议结构：

```json
{"spaceId":"uuid","generation":"uuid","upperBound":120,"nextCursor":100,"hasMore":true,"changes":[]}
```

以上仅展示结构，真实 nextCursor 必须由返回的已处理变化确定，不能像示例空数组一样跳过未返回事件。页面大小同时受数量和字节上限约束。客户端处理变化与落盘游标原子提交；附件可处于明确的待下载状态，保留元信息并重试。

上传接口的成功 seq 不能直接设置全局拉取游标，否则会跳过其他设备的变化。手机需保存编辑时的 baseRev，编辑失败或网络断开保留当前输入，不能假装保存成功。

错误码至少覆盖：UNAUTHORIZED、PROTOCOL_UNSUPPORTED、SPACE_CHANGED、REV_CONFLICT、INVALID_RECORD、BLOB_MISSING、PAYLOAD_TOO_LARGE、QUOTA_EXCEEDED、RATE_LIMITED。4xx 中需要用户介入的错误停止无意义重试；网络和暂时性 5xx 退避重试。

## 13. 首次合并与冲突处理细节

首次启用先备份本地并拉取有界远端快照，再计算合并，不能直接把整份本机库覆盖远端。相同 ID 内容比较使用规范化业务字段（排除服务器 rev、同步状态和纯展示时间差）。内容不同且无共同基线，保留远端原 ID，本地版本复制成新 UUID，并记录原 ID 和来源设备用于解释；这个映射须持久化，重启不能重复生成副本。

如果远端同 ID 是墓碑且本地没有共同基线，不能直接恢复原 ID：展示删除冲突，允许另存新记录或接受删除。已有共同基线的冲突在本地持久保存双方及远端 rev；即使拉取游标继续前进，也不能丢掉待处理版本。

冲突页面只做三种操作：保留本机、保留云端、保留两份。保留两份用新 ID 写一份；上传失败仍保留本地副本。引用及附件随所选内容一起处理，不把正文和引用拼成失去出处的新记录。

同步周期建议：修改后 2 秒防抖，开启且插件运行时每 30 秒检查一次；失败从 5 秒退避到最多 5 分钟，添加抖动；立即同步跳过等待但不启动第二条并行循环。只在有差异时显示操作，不每轮弹提示。

## 14. 本机设置 API 与安全边界

由 Host 提供读取脱敏配置、提交配置、测试连接、开启/关闭、立即同步、查看状态和处理冲突的接口。前端首次输入 Token 后交给 Host，随后读取只得到 hasToken，不读回原值；“显示”只显示当前输入，已存 Token 只允许替换。

这些接口不是公网管理 API：沿用 DSH 的认证/会话边界，写操作校验来源和 CSRF，不允许任意网页配置云地址并导走本地笔记。若宿主实际没有可用认证，必须明确并实现可行的本地授权边界，不能假设同源就天然安全。新的服务器 API 不复用本机 routes.js 暴露整个 Host。

手机网页复用同一 record 和 op 逻辑；列表先分页、搜索个人规模可用 SQLite 文本查询，暂不做语义搜索。部署端提供创建/撤销设备 Token、设置手机口令、备份、恢复管理命令，不做可公开注册的管理后台。
