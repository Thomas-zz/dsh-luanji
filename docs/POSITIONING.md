# 乱记（dsh-luanji）· 产品定位

## 一句话

**DSH 里的想法收集器：用想法勾勒你的形状。**

像 Flomo 一样轻，但零切换——它长在你和 AI 碰撞想法的地方。现在是本机版，未来上云端、多端同步，DSH 始终是那个入口。

## 概览

- **面向谁**：用 DSH 和 AI 结对工作的人——想法在对话里碰撞，也想在对话里留住。
- **解决什么问题**：灵光一现稍纵即逝；Flomo 们还要切换软件。它长在 DSH 里，零切换，火花随手接住。
- **主要功能**：侧栏随手记（⌘↩ 保存、草稿自动存）· 划选对话让 agent 代记（只在你明确开口时）· 模糊搜索找回 · 导入导出 · 纯本机。
- **目前成果**：插件已装进 DSH 客户端实际可用；11 项测试全绿 + ego-browser 全流程回归通过；自带本地开发服务器，具备单独开源条件。

## 产品哲学

### 一、灵感的半衰期极短，记录的摩擦要趋近于零

想法不是等你想清楚了才值得记——半句话、一个疑问、一次碰撞的余温，都值得原样留下。所以乱记把结构化的成本从记录时拿走：不要标题、不要标签、不要决定"它属于哪"。写下来就完了，整理是以后的事，或者永远不整理。

### 二、工具应该住在碰撞发生的地方

和 AI 对话，是当下想法密度最高的场景。Flomo 们再好，也在另一个窗口里——切换本身就是流失。乱记长在 DSH 里：侧栏点开就写，划选对话就能存，火花在熄灭之前就被接住。位置，就是它的核心功能。

### 三、不假装解决"记忆"

记忆和知识库是真正的难题，很多产品假装解决了它：自动总结、自动归档、替你记住一切——结果是噪音、失真和不被信任。乱记选择克制：Agent 只在你明确开口时才动手，记的是你的原话，不做加工。机器的线永远只是临时的，人的记录永远是原文。

### 四、不制造整理债务

没有未归档数，没有连续打卡，没有"你还有 47 条没整理"。回看是记录的奖赏（模糊搜索、意外重逢），不是第二份工作。一个工具如果靠制造焦虑留人，它就已经失败了。

### 五、沉淀的不是档案，是形状

想法攒起来，不是为了建一个关于你的数据库，而是让想法自己显影出你的形状——你在关心什么、反复回到哪里、哪些火花一直在烧。你因此更了解自己；懂你的 Agent 也因此能从你的想法里，碰出新的火花。价值是双向的、复利的。

### 六、数据是你的，先本机，后云端

现在一切都在本机一个 JSON 文件里，随时导出走人。未来的云端和多端同步是一次明确的边界变化，会明说——而不是默认把你的念头传上去。信任不是功能，是地基。
